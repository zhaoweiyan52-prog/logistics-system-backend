2. **MySQL服务重启、Java进程重启后的订单与会话保留**。代码设计使用数据库持久化，实际重启验证仍需MySQL环境。
3. **真实MySQL事务隔离、并发锁行为、字符排序和时区往返**。当前并发与ISO时间结果来自H2；连接URL已明确设置UTC及会话时区，仍需真实数据库确认。
4. **浏览器内完整交互和视觉检查**。已验证HTTP、资源访问与JS语法，未宣称点击完成所有界面功能。原页面会主动调用下一阶段接口，错误提示是已知的阶段范围差异。

6. HTTPS部署、短信签收、正式计费、生产负载等不属于本阶段验证。

## MySQL具备后怎么补验

按README先执行建库建表SQL，设置DB_URL/DB_USERNAME/DB_PASSWORD，启动默认配置，再运行 `scripts/verify-api.ps1`。在MySQL中检查用户哈希、订单及轨迹，然后停止并重启Java进程，用自己的账号重新登录并查询原订单。通过后再更新本记录，不要用测试profile代替默认MySQL配置。

如要复现本次临时H2的HTTP校验，可执行下面命令；它只用于开发检查，退出就丢失数据：

```powershell
& .\scripts\mvn.ps1 '-Dspring-boot.run.useTestClasspath=true' '-Dspring-boot.run.arguments=--server.port=18081 --spring.config.additional-location=file:./src/test/resources/application-test.yml' spring-boot:run
```

另开窗口运行HTTP校验脚本。**这个命令运行成功仍不能记作MySQL通过。** 正常启动请使用README的MySQL步骤。
