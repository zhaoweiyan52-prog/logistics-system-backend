# 接口核对与待确认问题

核对依据：用户指定的 `API_CONTRACT.md`、`logistics-admin.html`、`mock-server.js` 及三份前端静态依赖。当前目录初始为空，已读取外部原文件，并把接口材料原样复制到 `reference/`。外部文件中的执行建议、交付自查清单和“已验证”段落是参考资料，不作为用户本次要求额外完成全部系统的指令。

## 本阶段字段对齐

| 内容 | 文档 / 页面 / mock | 本后端 |
|---|---|---|
| 请求根路径 | `http://localhost:8080/api` | `/api`，默认 8080 |
| 登录参数 | 页面 account/pwd 转成 username/password | username/password |
| 注册参数 | username/password/role | 原字段；role 必须为 customer/staff |
| 认证返回 | token/role/name/account | 原字段，不返回密码、内部用户编号 |
| 认证头 | Bearer token | 真实随机凭证，数据库校验 |
| 创建订单 | receiver/dest/goods/weight/fee | 全部保存；不接收客户端指定订单归属 |
| Order 字段 | no/goods/dest/receiver/fee/status/time/eta/signCode/traces/fb；mock 另有 weight | 全部返回，包含 weight |
| traces | `{t,txt,done}`，时间正序 | 初始一条，数据库保存，按时间/id 排序 |
| 列表 | `{list,total}`，page 从1，size默认10 | 相同，total 为归属+关键词+状态过滤后的总数 |
| 关键词 | 页面“运单号 / 物品”；mock 查询 no/goods | 原语义，按字面值匹配；转义 `%`、`_`，绑定 SQL 参数 |
| 时间 | ISO 字符串供 normOrder 转换 | Java Instant 输出 ISO 8601 |
| 登出 | `{ok:true}`，凭证失效 | 删除当前 token 的数据库记录 |

## 已发现的冲突及当前处理

1. **阶段范围与页面全量加载冲突。** 用户只要求第一阶段六个接口；原文档交付清单要求全系统，且页面 `loadAll()` 登录后同时拉取任务、用户、库存、通知、统计等。本次只实现六个接口，其余已登录请求返回 `code:50101` 和中文未实现说明。未伪造统计或把后续功能冒充完成。原页面会弹多条未实现提示，完整首页联调需要后续阶段补齐接口，或由前端组员确认分阶段加载方案。本次未改页面业务流程。

2. **客户数据隔离与 mock 冲突。** mock 的 `/orders` 与详情返回全局 orders，订单没有 owner_id。根据用户明确要求，真实表增加内部 `owner_id`，列表、详情 SQL 都限定登录用户；不把它塞进前端 Order，也不增加前端必填字段。第一阶段员工/管理员也只查询本人创建的订单，不开放全局权限；后续员工分配、管理员全局查询范围待小组确定。

3. **注册角色规则不一致。** 文档明令不开放 admin 注册，但 mock 将所有非 staff 角色降级为 customer；mock 只校验密码下限，未校验20位上限。本后端按文档执行：customer/staff 可注册，admin/未知/缺失角色拒绝，密码6–20位。保留原路径及字段，不偷偷降级角色。额外限制 BCrypt 密码 UTF-8 编码不超过72字节，超限明确返回业务错误。

4. **页面角色切换不能代表授权。** 原页面 `switchRole` 只改本地视角，不能把客户变成员工或管理员。后端每次从 token 对应数据库账号读取真实身份，查询范围不随前端 role 参数变化。保留前端按钮，未新增可由客户自行提权的接口。

5. **运费来源尚未定义。** 页面按可编辑的 first/firstFee/addFee 算费并发送 fee，默认规则为首重1kg/12元、续重4元；mock 直接采用客户端 fee；文档没定义服务端计费或配置保存接口。本阶段保留 fee 入参并校验非负、金额至多两位小数后保存，不自行引入新的计费规则。**待确认：最终运费是否必须由后端按统一规则计算，以及客户传入 fee 与后端报价不一致时的处理。** 当前不能用于实际收费结算。

6. **运单号格式只约定唯一，没有约定长度或序列规则。** mock 示例为 SF+日期+进程内递增号，进程重启/多实例可能冲突。本后端仍返回 string 类型 no，使用 SF+日期+UUID，加数据库唯一主键。**待确认：如需固定长度、纯数字、校验位或某快递公司的规范，应先补充格式契约。** 不增加前端字段。

7. **登出是否免 token 的表述冲突。** 文档把 logout 列在“认证接口（无需token）”表中，但认证章节明确只有 login/register 免鉴权，mock 也要求 logout 携带 token。按后两者执行：logout 必须携带有效 token。

8. **业务错误的 HTTP 状态与错误提示。** 原前端 `req()` 对非2xx先抛“HTTP 状态”，不会显示 body 中 message；mock 的详情不存在使用 HTTP404。本后端业务失败（包括不存在或无权查看）使用 HTTP200+非0code，让页面显示具体中文原因；无效凭证严格用 HTTP401，内部故障用 HTTP500。路径、成功结构和业务错误体保持约定。

9. **前端默认值与演示内容会继续存在。** 原页面默认 USE_MOCK:true；本项目可运行副本仅改 USE_MOCK:false、BASE:'/api' 和三个本地依赖地址，其余业务代码原样保留。未在真实数据库创建演示账号，页面演示账号按钮不会自动获得真实账号。部分首页初始统计为前端零值，接口未实现时不能视作真实统计结果。

10. **文档数量统计有误。** 文档称“20个接口（3认证+17业务）”，实际表格逐行计数是21个（3认证+18业务）。本阶段明确实现6个，不以该总数错误遗漏或扩展范围。

## 未由文档定义的补充边界

这些是当前后端的明确输入边界，便于组员核对；如需变更应一起更新接口文档：

- 收件人≤100字，目的地≤500字，物品≤200字；三者不能为空。
- 重量0.001–99999.999 kg，最多三位小数；费用0–99999999.99元，最多两位小数。
- 页大小1–100，关键词≤200字；非法分页/状态参数返回业务错误，不静默改成默认值。
- 未约定的 JSON 字段拒绝，防止误写 owner_id/status/role 等字段；查询串中额外身份参数不参与授权。
- 默认预计送达为下单后3天，与 mock 一致，尚无真实路线及时效算法。
- signCode 按现有约定返回4位字符串，属于教学演示字段；真实身份核验和短信签收不属于本阶段。
- token 默认8小时，保存在数据库以支持重启后的会话；无刷新token接口，不擅自新增协议。
