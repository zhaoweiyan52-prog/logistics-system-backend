角色变更撤销目标用户全部旧 token；禁用立即撤销旧 token 并拒绝重新登录。不能禁用或降级最后一位启用的管理员。批量角色变更在事务中全部成功或全部回滚。

## 2. 旧数据库如何升级

先停止旧版后端。用有建表权限的数据库管理账号在 Workbench 执行：

```sql
USE logistics;
```

然后通过 **File → Open SQL Script** 打开项目里的 `sql/03-full-features.sql`，执行整份脚本。原有 app_users/auth_tokens/logistics_orders/order_traces 及业务数据保留；增加 9 张表，并为旧的未结束订单补一个待办。脚本可重复执行，不会再次生成已有的待办。

不要对已有库重跑 `sql/02-schema.sql`：旧版部分独立 CREATE INDEX 语句不是幂等的。

全新电脑/全新库：执行 `01-create-database.sql`，选择 logistics，执行新的 `02-schema.sql` 一次即可，已包含全部 13 张表，无需再执行 03。

应用账号应仍只授予 logistics.* 的 SELECT/INSERT/UPDATE/DELETE；升级由管理账号完成，不必给应用账号 CREATE/DROP 权限。当前本机与 Aiven 业务库已升级，不需要重新执行建表。

## 3. 首位管理员如何启用

没有默认管理员账号或默认密码，也不能从注册接口提交 admin 自行提权。

1. 完成上面的数据库升级，打包并正常启动后端，在网页注册一个你自己使用的账号。密码只在本机网页输入。
2. 关闭后端。在启动它的 PowerShell 中指定这个**已有账号的用户名**：

```powershell
$env:BOOTSTRAP_ADMIN_ACCOUNT = '替换为你已注册的用户名'
& .\scripts\start-mysql-backend.ps1
```

3. 启动过程仅在数据库还没有任何管理员时提升该账号，并撤销它原先的登录凭证。重新登录后进入管理员页面。
4. 以后启动前移除这项环境变量：

```powershell
Remove-Item Env:BOOTSTRAP_ADMIN_ACCOUNT -ErrorAction SilentlyContinue
```

IDEA 运行可在 LogisticsApplication 的运行配置中临时添加同名环境变量；不把数据库密码或运行配置提交 Git。已有管理员后，其他管理员由“用户管理→角色分配”产生。

## 5. 状态与事务逻辑

客户下单 → pending（生成揽收待办）→ 员工更新 transit（完成揽收，生成下一待办）→ delivering（生成签收待办）→ 客户签收或员工确认 delivered。每次有效变更写入真实轨迹；客户签收会结束剩余待办。

pending/transit/delivering 可报 exception；异常处理后可回到 transit/delivering。delivered/cancelled 不允许员工再随意改动。每个流程步骤对应一条任务记录，因此“已完成”是完成步骤数，不是唯一运单数。

同一运单操作使用数据库行锁，防止两名员工重复完成；MySQL REPEATABLE READ 下任务重读使用 FOR UPDATE，避免旧快照。库存先锁仓库，按“仓库+物品”判断剩余数量，更新库存、容量和流水在同一事务中提交，不允许负库存或超过容量。

## 6. 需要小组继续确认的差异

- **图中的独立服务**：当前是一个 Spring Boot 应用中的逻辑模块，没有拆分微服务。
- **仓储和运单**：原库存接口没有运单号，qty 单位也未定义。当前库存与运单独立，按统一数量单位计算容量，不会把入库偷偷改成订单状态；页面删掉了未确认的“托”单位。
- **任务分配**：接口没有 assignee/分配接口，采用员工共用任务池并记录实际操作员。上门揽收地址沿用原 Task 的 addr；原下单表单没有寄件地址，暂用订单 dest 展示，不能当成真实上门地址。若要上门揽收需统一新增寄件人/寄件地址字段。
- **状态名称**：保持原前端 6 个状态，没有增加“已入仓/已打包/已送达未签收”。取消、反馈回复、仓库配置管理没有原页面接口入口，本次未新增这些业务流程。
- **运费**：保留原接口 fee，由页面读取数据库规则后报价，服务端校验精度及范围后保存。尚未约定服务器重新计价或报价过期处理，不能用于真实收费结算；旧订单不会随规则改变重算。
- **签收与凭证**：保留教学用 signCode；员工可按原页面直接确认已签收，也可由客户凭码签收。没有短信、真实身份验证或电子签名；原凭证接口只定义上传，没有增加公开下载链接。
- **通知设置**：签收/异常开关控制之后新事件的站内通知，历史通知不删除。mktNtf 控制把当前公告加入站内通知，不发送短信、邮件或外部营销；已读状态沿用页面本地行为，刷新后恢复未读。
- **账号管理**：已完成原页面的角色与启停功能；图中的账号新增/编辑、密码重置没有原页面接口，本次没有凭空设计。

表格组件自闭合写法会在直接加载 HTML 时被浏览器错误嵌套，已统一改为显式结束标签，修复员工和管理员表格错列。真实模式隐藏了虚构网点数、日均运单、准时率和折扣文案。
