# 第一阶段前端接口加载修复

原页面登录后 loadAll() 同时请求全部业务模块，下单后还会刷新统计接口；真实后端只实现认证及订单接口，因此即使登录和下单成功，页面也会反复弹出“该接口或请求方法未在第一阶段实现”。

## 改动

- 默认 `CONFIG.PHASE_ONE:true`，只在真实模式生效；mock 模式继续保留完整演示。
- 第一阶段登录、注册、刷新会话只请求订单接口，不请求统计、任务、库存、仓库、用户或通知。
- 下单后的统计刷新和未开放模块的分页/筛选监听在第一阶段直接跳过，不向服务器发请求。
- 客户首页改为寄件、订单和轨迹入口，去掉没有数据来源的统计零值。
- 暂不展示签收、反馈和通知控件；员工/管理员看到明确的功能说明页，不显示未完成的工作台。
- 真实模式不展示 mock 演示账号；第一阶段角色只随登录账号变化，保留退出及切换账号入口。
- 保留已实现接口的真实错误提示，包括业务错误、网络/HTTP失败及401，未采用统一吞掉错误的处理。
- 过期会话退出时不再重复调用 logout，避免401引起递归请求；退出时清理订单视图。
- 后端接口、JSON字段和数据库结构未修改；reference目录中的原始页面保持不变。
