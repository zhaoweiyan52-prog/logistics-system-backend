## 浏览器登录 403 的定位与修复

自动化请求未带 Origin 头，不能代替浏览器验收。实际浏览器请求带公网 HTTPS Origin，被过早执行的 CORS 过滤器与代理内部 HTTP 地址比较后拒绝，返回 403 Invalid CORS request。

修复提交 `7b6b5e5`：将 CorsFilter 放在 Spring Boot ForwardedHeaderFilter 之后，先恢复公网协议和主机名，再判断同源。不设置通配来源，不关闭鉴权。

增加 ProxyCorsTest：模拟代理内 HTTP、公网 HTTPS 和转发头，确认同源登录进入认证逻辑，同时拒绝不可信来源。包含新用例的 37 项 H2 测试通过。

该修复已在 Render 上线。线上带真实站点 Origin 的登录探针已进入账号认证逻辑（HTTP 200 + 业务错误码，而非 CORS 403）；带不可信 Origin 的请求仍返回 HTTP 403。携带站点 Origin 的完整 23 项线上业务检查再次全部通过，/health 返回 UP。
